# Как вносить правки в учебник

Спасибо, что помогаешь улучшать учебник. Это образовательный материал, поэтому главные критерии — точность, воспроизводимость примеров и единый стиль.

## Базовые правила

1. Соблюдай [STYLE_GUIDE.md](./STYLE_GUIDE.md): структура главы, объём, тон, оформление кода и ссылок.
2. Код должен быть исполняемым, с указанием языка после открывающего fence.
3. Версии инструментов и образов фиксируй конкретными тегами, не используй `latest`.
4. Секреты, пароли и приватные ключи не добавлять ни в текст, ни в примеры.
5. Новые главы добавляй только вместе с обновлением `index.md` раздела и сайдбара в `astro.config.mjs`.
6. Внутренние ссылки делай без base-префикса: `/07-nestjs-api/rest-design/`.

## Проверка перед PR

```bash
npm ci
npm run build
npm run preview
```

После сборки проверь:

- новая страница открывается и попадает в sitemap;
- в сайдбаре нет битых slug;
- «Типичные ошибки и грабли», «Вопросы на собеседование», «Практика» и «Что почитать» присутствуют;
- объём главы — 1800–2600 слов без учёта кода.

## Что особенно ценится

- воспроизводимые примеры команд и docker-compose;
- ссылки на первоисточники вместо вторичных туториалов;
- честные разделы «плохо/хорошо»;
- замеченные устаревшие версии, битые ссылки и неработающие примеры.

Если сомневаешься, открывай issue с описанием проблемы и ожидаемого результата.
